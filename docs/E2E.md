E2E тестирование (локально)

Цель
- Поднять локальное окружение, применить миграции, выполнить розыгрыш (draw) и сгенерировать превью уведомлений для отправителей.
- Проверить, что уведомления логируются в `notification_logs` и что напоминания работают по настройкам.

Подготовка
- Убедитесь, что у вас есть Python 3.11+ и Docker (опционально).
- Установите зависимости в виртуальном окружении (опция для локального запуска без Docker):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Для запуска тестов/инструментов может понадобиться установить pytest отдельно
pip install pytest
```

Шаг 1 — применить миграции

Если вы используете локальную БД (например, sqlite), выполните:

```bash
# из корня проекта
alembic upgrade head
```

Если вы используете Docker Compose (рекомендуется для совпадения окружения):

```bash
# собрать и запустить контейнеры (если нужно)
docker compose up --build -d
# выполнить миграции внутри контейнера (пример: сервис называется secret_santa_bot)
docker compose run --rm secret_santa_bot alembic upgrade head
```

Шаг 2 — выполнить пробный розыгрыш и вывести превью уведомлений

Локально (в venv):

```bash
python3 scripts/run_draw_and_preview.py
```

В контейнере:

```bash
docker compose run --rm secret_santa_bot python3 scripts/run_draw_and_preview.py
```

Ожидаемое поведение:
- Скрипт создаст тестовые записи (если в БД меньше 2 completed записей) и выполнит draw.
- В консоли вы увидите превью сообщений для каждого `giver`.

Шаг 3 — превью режима отправки администраторам

Скрипт `scripts/send_notifications_to_admins.py` отправляет сообщения только администраторам, если `SEND_REAL_NOTIFICATIONS=False` (по умолчанию).

Чтобы выполнить превью (не отправляя реальным пользователям):

```bash
python3 scripts/send_notifications_to_admins.py
# или в контейнере
# docker compose run --rm secret_santa_bot python3 scripts/send_notifications_to_admins.py
```

Шаг 4 — проверить таблицы в БД

- Проверьте таблицу `notification_logs`: статус `pending`/`sent`/`failed`.
- Проверьте таблицу `assignments`: `sent_status` должен оставаться `pending` до подтверждения (кнопкой или callback).
- Проверьте таблицу `settings`: сохранённые значения из админки.

Пара полезных sqlite3 команд (если используется sqlite):

```bash
sqlite3 dev.db
# посмотреть таблицы
.tables
# посмотреть последние записи в notification_logs
SELECT id, user_id, notif_type, status, sent_at, attempts FROM notification_logs ORDER BY id DESC LIMIT 20;
``` 

Ручное тестирование интерактивно (через Telegram)

1. Запустите бота локально или через Docker Compose.
2. Отправьте /start боту и нажмите `Тайный Санта (с подарками)` — пройдите регистрацию.
3. Повторите для как минимум двух пользователей (можно использовать тестовые аккаунты или временно ввести telegram_id в базу для пользователей).
4. В админке нажмите `Розыгрыш` -> `Уведомить` и проверьте, что уведомления отправляются или логируются.
5. Нажмите inline-кнопку `Подарок отправлен` от имени отправителя (или нажмите соответствующий reply-кнопку) и убедитесь, что `assignments.sent_status` изменился на `sent`, а получатель получил уведомление (или запись в `notification_logs`).

Отладка
- Логи бота выводятся в `logs/` (если настроено). Просмотрите их для детальной информации.
- Если уведомления не отправляются — проверьте `bot/config.py`: `SEND_REAL_NOTIFICATIONS`, `ADMIN_IDS`, `BOT_TOKEN`.

Контакт и помощь
Если нужно, могу подготовить более автоматизированный E2E-скрипт или добавить docker-compose target, который выполняет миграции и тестовый запуск автоматически.
